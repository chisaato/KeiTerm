## 背景

现状（2026-10-17，`main@e4cf7a9`）：

- 上传/下载在 `RemoteFileManagerViewModel.Transfers.cs` 中直接并发执行，没有上限，没有排队。
- 同名目标静默覆盖（`FileMode.Create`），不支持目录。
- SFTP 上传在取消或失败时会在远端留下残缺文件；下载遇到普通异常时也不会清理本地文件。
- 下载目标固定为桌面。
- 每个目录标签各有一份 `TransferTasks`，彼此不可见。
- `ScpRemoteFileSystem` 读写都把整个文件缓冲在内存里。

本轮只补后端传输能力，以及让它可用所必需的最少界面。传输队列放在界面哪个位置，留待后续讨论。

## 目标行为

### 传输队列

- 每个**连接**一个传输队列。该连接的侧栏、文件标签、目录标签看到并操作的是同一个队列，暂时沿用现有活动抽屉呈现。
- 连接断开、重连或关闭时，队列整体取消；取消不算失败，不触发重试。
- 队列只存在内存中，退出应用即清空（ADR-0002）。
- **并发数**：设置项，最小值 1，不设上限，默认 3。超出部分排队，按加入顺序依次开始。SCP 不使用该值，固定为 1。
- 传输不走浏览通道（ADR-0002）。生产端点创建失败时传输不可用，只报告原因，不回退浏览通道；浏览仍可用。
  - SFTP：每个连接一条专用传输连接。首次 Acquire 才建立，无未归还租约且空闲 60 秒后关闭，随所属连接关闭。并发任务在这条连接上各开独立文件流。
  - SCP：另建一个 `ScpRemoteFileSystem`，与浏览实例隔离。Acquire 时才连接，连接与关闭串行。该实例不能被多个任务同时使用。

### 传输任务

- 对象可以是文件或目录，多选时每个选中项各成为一个任务。
- 下载入口：
  - "下载"：存到默认下载目录（新增设置项，默认是系统的"下载"文件夹）。
  - "下载到…"：用系统文件夹选择框选目标目录。
- 上传入口不变：拖入文件视图、上传命令；拖入的目录也要支持。
- **目录递归**：
  - 目标目录已存在时合并进去，冲突逐个文件处理。
  - 空目录照样创建。
  - 符号链接：指向文件的，传其内容；指向目录的，不进入并跳过。断开的链接跳过。权限不足或无法区分的探测记为无法确认，跳过，不标成断开，也不读写目标。
  - 部分文件路径，以及目标路径上的符号链接、重解析点或目录，拒绝跟随、删除和打开。远程用非跟随属性检查。检查与打开之间仍有竞态，远程不能消掉 TOCTOU，不能当作绝对安全。
- 传完的文件保留源文件的修改时间（远程用 `SetLastWriteTimeUtc`），不保留权限。

### 部分文件与续传

- 上传和下载都先写入同目录下的 `<文件名>.keipart`。确认长度与开始前重读的源大小一致后，再改成正式文件名。大小一致不是校验和，本轮不新增校验和或续传元数据。
- SFTP 覆盖式改名优先 `RenameFile(..., isPosix: true)`（`posix-rename@openssh.com`）。服务器没有该扩展且目标已存在时，抛 `TransferAtomicOverwriteUnsupportedException`，不删除旧目标，也不改名；已完成的部分文件保留。目标不存在才普通改名。其它失败不退回「先删再改名」。
- 长度确认之后的发布失败不再按续传开关删除部分文件。复制尚未完成时才适用清理规则：续传关则删除，续传开则保留。
- **续传开关**：设置项，默认**关**。
  - 关：遇到已有的部分文件就删除，从头传；复制未完成的失败或取消也删除部分文件。
  - 开：仍不保证能续。`PreviouslyRecordedSource == null` 表示没有可信历史（新任务、没有快照、跨重启残留），从 0 重传，不是「源未变化」。
  - 非 null 只表示同一次运行里、写流成功打开后提交的源事实。开始前重读源的大小和修改时间，任一不一致就从 0。队列还要求内存中的路径所有者世代仍有效；别的任务取得重叠路径后世代作废，历史清空，从 0。
  - 历史只在执行器按决定处理完旧部分文件、并且对应写流成功打开之后，经 `OnPartialWriteStarted` 提交当时读到的现场源事实，不是 `request.Source`。在此之前失败不得更新历史。
  - 退出应用后队列清空。磁盘上的旧部分文件没有可信来源，不能续传，必须重传。
- **SCP**：不支持续传，不受续传开关影响；目录递归和冲突策略照常生效。单个文件超过 512 MiB 时，开始前给出提示，因为 SCP 会把整个文件读进内存。本轮不改成流式。

### 冲突

- 冲突只针对正式文件名，部分文件不算冲突。
- 冲突策略有五种：覆盖、跳过、目标较旧才覆盖、自动改名（`name (1).ext`）、每次询问。
  - 新增设置项"默认冲突策略"，默认值为"每次询问"。
- 选"每次询问"时，经 `IInteractionService` 弹窗，弹窗内带"对本批次剩余的冲突都这样处理"的勾选。
  - 批次 = 一次用户操作产生的所有任务。
  - 弹窗等待期间，只暂停这一个任务，其他任务继续传。
- "目标较旧"按修改时间比较，允许 2 秒误差。
- 选了"跳过"的任务算完成（结果为已跳过），不算失败。

### 失败与重试

- 失败分为三类：

  | 类别 | 例子 | 是否自动重试 |
  |---|---|---|
  | 暂时性 | 传输连接中断或超时、`SSH_FX_CONNECTION_LOST` / `SSH_FX_NO_CONNECTION`、套接字异常、握手被拒或被丢弃 | 是 |
  | 永久性 | 权限不足（远程 `PERMISSION_DENIED`，本地 `UnauthorizedAccess`）、源文件不存在、本地磁盘已满、文件名不合法、文件被占用 | 否，显示原因 |
  | 无法判断 | SFTP v3 笼统的 `SSH_FX_FAILURE` 等 | 否，按永久性处理 |

- **重试设置**：
  - 自动重试开关，默认开。
  - 重试次数，默认 3。
  - 退避方式：固定间隔 / 指数退避，默认指数退避。
  - 初始间隔，默认 2 秒。
  - 最大间隔，默认 60 秒。
- 第 n 次重试（从 1 开始）前等待：固定间隔时为初始间隔；指数退避时为 `min(初始间隔 × 2^(n-1), 最大间隔)`。
- 重试不自动续传。只有续传开着、协议支持、写流成功打开后提交过的源事实仍在、路径所有者世代仍有效，且开始前重读的源大小和修改时间仍一致，才从部分文件长度续传；否则从 0。
- `TransferPathRejectedException` 与 `TransferAtomicOverwriteUnsupportedException` 是永久性失败。长度不一致仍是暂时性。
- 每个失败任务都有"重试"操作；队列有"重试全部失败项"。

## 不在本轮范围

以下都记为后续事项，本轮不做：

- 传输队列在界面上的位置与形态（单独讨论）。
- 多条传输连接（FileZilla 式），等实测发现带宽跑不满再做。
- 只建文件连接、不开 shell 的连接方式。
- 本地文件面板、目录同步与对比。
- 独立文件窗口（ADR-0001 已否决）。
- 终端上传并入传输队列。终端上传以 ZMODEM/YMODEM 为主，保持独立通道。
- 终端上传新协议：Kermit、trzsz。
- SCP 改为流式读写。
- 跨应用重启恢复传输队列，以及为残留部分文件补可信来源（ADR-0002 已否决，不新增元数据）。
