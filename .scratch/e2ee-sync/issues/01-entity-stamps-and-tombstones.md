# 01 同步实体记账与墓碑（预重构）

Status: ready-for-agent
Blocked by: None (can start immediately)

见 `../spec.md`「同步实体与本地记账」。

**要做什么：** 让本机数据具备合并所需的记账，但本机的可见行为不变。每个同步实体都记录最后修改时间与设备标识；删除改为写墓碑，读取时一律看不到墓碑。这一张不涉及任何同步逻辑或界面。

- [ ] 会话树节点、身份、代理、端口转发、外部编辑器、文件关联的删除改为写墓碑。原本靠外键级联删除的子实体（子树、会话配置、端口转发、秘密、编辑器路径、文件关联）由仓储显式写墓碑。
- [ ] 所有读取路径（含启动时组树）排除墓碑；在 UI 上删除后的表现与之前一致。
- [ ] 通过追加迁移给端口转发、known_hosts 补修改时间列，新建记账表，记录设置项、Profile、连接元数据键的修改时间、设备标识与墓碑。不修改已发布的迁移。
- [ ] 保存设置项、Profile、连接元数据键时刷新对应记账；连接元数据仍不改所属会话的 `revision`。
- [ ] 秘密（身份秘密、代理密码）的写入会刷新所属身份或代理的修改时间。
- [ ] 本机 `revision` 在每次用户修改时递增，后台写入的元数据除外。
- [ ] 提供按「早于某时间」物理清理墓碑的仓储能力（供 03 调用）。
- [ ] 现有仓储测试改为断言：删除后读取不到、墓碑存在、子实体也写了墓碑；全量测试通过。
