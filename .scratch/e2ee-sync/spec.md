# 端到端加密同步

Status: ready-for-agent

术语以 `GLOSSARY.md`「同步」一节为准；形态决策见 `docs/adr/0004-e2ee-sync-single-age-snapshot.md`。`docs/design/05-cloud-sync-and-plugins.md` 已被取代。

## Problem Statement

用户在多台电脑上使用 KeiTerm，每台都要重新建会话树、导入私钥、配主题和设置。手动复制数据库既危险（秘密离开保险库）又会互相覆盖。市面上的同类产品要么把数据交给厂商服务器（Termius、Tabby Web），要么只是整库备份/恢复，没有合并（Cherry Studio）。用户想要的是：数据放在自己选的存储上，存储方看不到任何明文，多台设备各自修改后能合并，不会互相吞掉对方的修改。

## Solution

设置里新增「同步」页。用户选一个同步位置（本地目录、WebDAV 或 S3 兼容存储），设定同步口令。KeiTerm 把全部应用数据（会话树与会话配置、连接元数据、身份及其秘密、代理及其秘密、端口转发、known_hosts、外部编辑器与文件关联、应用设置、Profile）打成一个整库快照，用 age 口令模式加密成同步包，上传到同步位置。另一台设备填同一个同步位置和同步口令即可加入：下载、解密、与本机数据按同步实体合并，再上传合并结果。

只有本机专属项不同步：窗口位置与尺寸、最近打开的目录、快速解锁登记、同步配置本身。

同步在启动时、本地修改后、运行期间定时以及手动点击时进行。启用/加入同步前必须先给本机保险库设置主密码；无主密码模式仍可正常使用不同步的功能，但不能初始化、加入或执行后台同步。同步口令保存在本机保险库里，所以保险库锁定期间同步暂停。更换同步口令会重新加密同步包，没拿到新口令的设备不能解密后续新包，但不能撤回已下载数据或撤销存储账号访问权限。

合并出错时有两道安全网：本机保留合并前快照，同步位置保留最近几个历史同步包，都可以在同步页恢复。

## User Stories

1. 作为多机用户，我想在设置里选择一个本地目录作为同步位置，以便借助 Syncthing、Dropbox、iCloud Drive 等同步盘在设备间传递数据。
2. 作为自建网盘用户，我想填写 WebDAV 地址、用户名和密码作为同步位置，以便使用 Nextcloud、群晖或坚果云。
3. 作为对象存储用户，我想填写 S3 兼容存储的端点、区域、桶、前缀和访问密钥作为同步位置，以便使用 AWS S3、Cloudflare R2、MinIO 或国内对象存储。
4. 作为用户，我想在保存同步位置前点击「测试连接」，以便立即知道地址或凭据填错了。
5. 作为第一台设备的用户，我想设定同步口令并完成首次上传，以便其他设备之后能加入。
6. 作为新设备的用户，我想只填写同步位置和同步口令就加入同步，不需要登记或审批，以便快速上手。
7. 作为新设备的用户，口令错误时我想得到明确的「同步口令不正确」提示，并且本机数据不受任何影响。
8. 作为本机已有数据的新设备用户，首次加入时我想选择「合并」「以同步位置为准」或「以本机为准」，默认合并，以便不会意外丢失任何一边的数据。
9. 作为用户，同步位置为空时，我想直接用本机数据初始化同步包，不被要求做选择。
10. 作为用户，我想让会话树的文件夹、会话及其配置、排序都参与同步，以便每台设备看到同一棵树。
11. 作为用户，我想让身份连同私钥、私钥口令和密码一起同步，以便新设备不需要重新导入密钥。
12. 作为用户，我想让代理及其密码、端口转发规则一起同步。
13. 作为用户，我想让 known_hosts 中已信任的主机密钥同步，以便在新设备连接时不再重复确认指纹。
14. 作为用户，我想让连接元数据（如能力探测结果）同步，因为它描述的是服务器，换一台设备也成立。
15. 作为用户，我想让外部编辑器的定义（含按操作系统区分的可执行文件路径）和文件关联同步，以便我在所有 Linux 机器上都用同一个 `code`。
16. 作为用户，我想让应用设置和 Profile（主题、配色、字体、终端外观等）同步。
17. 作为用户，我想让窗口位置、最近打开的目录、快速解锁登记和同步配置本身留在本机，以便不同屏幕、不同网盘账号的设备互不干扰。
18. 作为用户，我在设备 A 改了主题、在设备 B 改了字体，我想两处修改都保留，因为它们是不同的设置项。
19. 作为用户，我在两台设备上改了同一个会话，我想保留最后修改的那一份，并且结果确定、可预期。
20. 作为用户，我在设备 A 删除了一个会话，我想它在其他设备同步后也消失，而不是被它们重新带回来。
21. 作为用户，我在设备 A 删除了一个文件夹，同时在设备 B 修改了其中一个会话，我想被修改的会话保留下来并移到根目录，以便最新的修改不会丢失。
22. 作为用户，如果一次同步会删除大量数据（超过 30% 或 50 个同步实体），我想让自动同步暂停并请我确认，以便防住同步位置异常或误操作造成的批量删除。
23. 作为用户，合并后某个会话引用的跳板、代理、身份或 Profile 已被删除时，我想看到这个会话标记为「配置不完整」，而不是同步失败或连接时崩溃。
24. 作为用户，我想在启动时、修改后约 30 秒、运行期间每 5 分钟自动同步，并且随时可以点「立即同步」。
25. 作为用户，我想在同步页看到上次同步的时间、结果，以及是哪台设备最后写入了同步包。
26. 作为用户，同步失败（网络、凭据、口令、同步包损坏）时，我想看到可读的原因，本机数据保持不变。
27. 作为用户，保险库锁定时，我想看到「保险库已锁定，同步暂停」，解锁后自动继续。
28. 作为用户，我想更换同步口令，以便让丢失或不再信任的设备无法读取今后的数据；其他设备在下次同步时会提示我输入新口令。
29. 作为用户，我想停用同步，并选择是否删除同步位置中的同步包；停用不影响本机数据。
30. 作为用户，合并结果不对时，我想从本机最近 10 份合并前快照中选一份恢复。
31. 作为用户，我想从同步位置最近 5 个历史同步包中选一份恢复，以便在所有设备都同步了错误数据后找回旧数据。
32. 作为注重隐私的用户，我想让同步位置只看到一个不透明的密文文件，看不到会话名、主机名或文件名中的任何信息。
33. 作为注重可移植性的用户，我想在没有 KeiTerm 的情况下用标准 `age -d` 加同步口令解开同步包，以便数据不被锁定在这个应用里。
34. 作为用户，两台设备几乎同时同步时，我想双方的修改最终都保留下来，即使同步位置不支持条件写。
35. 作为用户，我想在同步期间继续正常使用终端和文件传输，同步不阻塞界面。
36. 作为用户，我在一台设备上修改了私钥口令或代理密码，我想这次修改也能同步出去，即使身份或代理的其他字段没变。
37. 作为用户，我想让同一台主机的同一个主机密钥在两台设备上各自信任过后，合并结果里只有一条，不会重复。

## Implementation Decisions

### 同步实体与本地记账

- 同步实体及其标识：
  - 会话树节点：节点 id，会话配置随节点走。
  - 身份：id，秘密随身份走。
  - 代理：id，秘密随代理走。
  - 端口转发、外部编辑器、文件关联：各自的 id；外部编辑器的按操作系统路径随编辑器走。
  - known_hosts：按自然键（主机、端口、公钥）。
  - 连接元数据：按（会话、键）。
  - 应用设置：按设置项。
  - Profile：按 Profile id。
- 每个同步实体记录最后修改时间（UTC）与修改它的设备标识。已有的 `updated_at` 继续使用；缺少修改时间的表（端口转发、known_hosts）通过追加迁移补列。
- 秘密的修改必须刷新其所属身份或代理的修改时间。
- 不在数据库表里的同步实体（设置项、Profile、连接元数据键）由一张新的记账表保存修改时间、设备标识和墓碑，通过追加迁移创建。
- 仓储的删除改为写墓碑（`deleted_at`）；读取路径一律排除墓碑。原本靠外键级联的删除（子树、端口转发、秘密），由仓储显式为每个子实体写墓碑。
- 墓碑保留 180 天，同步后清理过期的墓碑并物理删除对应行。
- `revision` 继续作为本机变更计数，用来判断「上次同步之后有没有本地修改」，不参与合并比较。
- 后台写入的连接元数据仍不改所属会话的 `revision`，只刷新该键的记账。
- 设备标识在首次同步时生成，属于本机专属项。

### 同步包格式

- 远端是一个对象：`keiterm-sync.age`，内容是 age v1 文件，使用单一 scrypt recipient（工作因子按 age 默认值 18）。
- 解密后是带格式版本号的 JSON 整库快照，包含：所有同步实体（含墓碑）及其修改时间和设备标识、写入方设备标识、写入时间。
- 读取到更高的快照格式版本时，拒绝合并并提示升级应用。
- 历史版本：每次上传前把当前同步包复制到 `history/` 下，按写入时间命名，只保留最近 5 份。
- age 实现：优先评估复用项目已依赖的 NSec（scrypt、ChaCha20-Poly1305、HKDF 已具备），自行实现 age 的 scrypt recipient 与 STREAM 分块格式；也可以引入 AgeSharp，但它目前仍是预览版，需要在工单里权衡后定。无论哪种实现，都必须通过 C2SP/CCTV 的 scrypt 相关向量。

### 同步协调器（Core）

- 一轮同步：
  1. 读取远端同步包及其版本标签（ETag，或文件的修改时间加长度）。
  2. 用同步口令解密。
  3. 导出本机快照。
  4. 合并。
  5. 合并结果有本机变化时，先保存合并前快照，再在单个事务里写回本机。
  6. 合并结果与远端不同时，加密并上传。
- 合并规则：
  - 逐个同步实体比较修改时间，取较新的；时间相同则取设备标识较大者。
  - 墓碑也是一个版本，参与同样的比较。
  - 若实体的修改晚于墓碑时间，保留该实体；它的父节点已被删除时，移到根目录。
- 并发：
  - 同步位置声明支持条件写时，上传带 `If-Match` 或 `If-None-Match`；返回冲突时重新执行整轮。
  - 不支持条件写时直接上传，然后读回，比较字节哈希与刚上传的内容；不一致就重新执行整轮。
  - 两种情况都最多重试 3 次。
- 安全阈值：合并会删除超过 30% 的本机同步实体，或超过 50 个时，自动同步中止并标记「需要确认」；手动同步弹出确认。
- 悬空引用：合并后不改写引用。读取时，引用目标不存在的会话被标记为「配置不完整」，界面上提示。
- 首次加入（本机从未同步过、远端有同步包）：交互服务询问合并、以同步位置为准、以本机为准，默认合并。远端为空时直接初始化。
- 更换同步口令：先用旧口令完成一轮同步，再用新口令加密合并结果上传，同时清空历史版本（历史仍是旧口令加密，否则旧设备仍可读取）。其他设备解密失败时，提示输入新口令。
- 启用/加入同步与任何后台同步入口都必须验证保险库已设置主密码，无主密码时在读远端/导入/上传之前拒绝并提示先设置主密码；不能等到需要写快照时才拒绝。保存同步口令也禁止在明文保险库中进行。未使用同步的无主密码模式仍可正常使用其他功能，不显示同步前置条件错误。
- 保险库锁定时不进行同步，状态为「保险库已锁定」。同步口令作为保险库条目保存。
- 合并前快照：在本机应用数据目录下保留最近 10 份，用 Vault Key 加密（其中含秘密）。恢复时，把快照作为本机数据写回，并刷新所有实体的修改时间，以便恢复结果在下次同步时胜出。
- 只要仍有本机恢复快照或换口令待续作凭据，就禁止移除保险库主密码；不自动删除备份、不转成明文，也不丢弃其解密能力。正常更换主密码/Vault Key 轮换继续保留可解密快照。删除快照必须由用户显式确认，待续作凭据必须先完成更换或明确停用同步后清除。

### 同步位置（`ISyncLocation`，Core 抽象，Infrastructure 实现）

- 能力：
  - 测试连接；
  - 读取主同步包（内容和版本标签，不存在时为空）；
  - 写入主同步包（可附带预期版本标签）；
  - 列出、读取、写入、删除历史同步包；
  - 声明是否支持条件写。
- 实现：
  - 本地目录：先写临时文件再原子改名；不支持条件写。
  - WebDAV：使用 `WebDav.Client`。按 ETag 条件写，默认开启；坚果云等不可靠的服务可在配置里关闭条件写，改走读回检查。
  - S3 兼容存储：使用 `AWSSDK.S3`。条件写按服务商默认，阿里云 OSS、腾讯云 COS 默认关闭；用户可手动切换。
- 同步位置的凭据（WebDAV 密码、S3 密钥）存放在保险库，同步位置配置属于本机专属项。
- 实现在程序集内注册，不做动态插件加载。

### 触发与界面

- 触发：
  - 应用启动且保险库解锁后同步一次；
  - 任何同步实体发生本地修改后，防抖 30 秒；
  - 运行期间每 5 分钟一次；
  - 手动点「立即同步」。
- 同一时刻只运行一轮；运行中再次触发时合并为下一轮。
- 设置窗口新增「同步」页，包含：
  - 同步位置类型与配置、测试连接；
  - 启用/加入、更换口令、停用（可选删除远端）；
  - 状态（上次时间、结果、最后写入设备、错误原因）；
  - 立即同步；
  - 从合并前快照恢复、从历史同步包恢复。
- 首次加入的三选一、批量删除确认、更换口令和口令错误时的输入，都走统一交互服务（见 `docs/design/10-refactor-plan.md`），不在 ViewModel 上加 `Func<>` 弹窗属性。

## Testing Decisions

- 好的测试只看外部行为：在一台设备上做操作、同步，然后观察另一台设备的数据。不断言内部调用顺序，也不只测 Mock。
- **接缝 1：同步协调器（主接缝）**
  - 测试里用两个或三个临时的「设备」，各有真实 SQLite 库、设置目录和保险库，共用一个本地目录作为同步位置。
  - 覆盖：
    - 各类同步实体往返；
    - 不同设置项的修改都保留；
    - 同一实体以最后写入为准，时间相同时按设备标识裁决；
    - 删除传播；删除后又被修改的实体保留并移到根目录；
    - 子树删除连带子实体；
    - 悬空引用；
    - 批量删除阈值；
    - 首次加入三个选项；
    - 口令错误时本机不变；
    - 更换口令后旧口令失效、历史已清空；
    - 保险库锁定时不同步；
    - 未设主密码时不能保存同步口令、初始化/加入/后台同步，且本机/远端不变；不同步的无主密码模式仍可保存普通数据；设置主密码后可正常启用；存在本机恢复快照或换口令待续作凭据时不能移除主密码；
    - 合并前快照恢复与历史同步包恢复；
    - 墓碑过期清理；
    - known_hosts 按自然键去重；
    - 秘密修改会刷新所属实体；
    - 本机专属项不进入同步包。
  - 并发：用一个可注入「上传后被别人覆盖」的测试同步位置，验证读回检查后会重新合并，双方修改都保留；同时验证带条件写的路径。
- **接缝 2：同步包格式**
  - C2SP/CCTV 的 scrypt 相关测试向量全部通过。
  - 本机装有 `age` 命令行时，验证双向往返：我们加密、`age -d` 解密，以及 `age -p` 加密、我们解密；未安装则跳过。
- **接缝 3：同步位置契约**
  - 同一套契约测试分别跑本地目录、WebDAV 和 S3：
    - 读取不存在的同步包；
    - 写入后读取一致；
    - 带过期版本标签的条件写被拒绝；
    - 历史版本的列出、轮转与删除。
  - 本地目录总是运行。WebDAV 和 S3 在 `KEITERM_SYNC_BACKEND_TESTS=1` 时运行，连接本机的 MinIO 与 WebDAV 服务。具体如何起服务，写在测试文件头部的注释里。
- 仓储层的软删除，复用现有仓储测试：断言删除后读取不到、墓碑存在、子实体也写了墓碑。
- 先例：
  - 跨进程、真实依赖的测试：`KEITERM_SSHD_TESTS`；
  - 真实 SQLite 加加密保险库的测试：快速解锁测试，见 `docs/design/14-vault-quick-unlock.md`。

## Out of Scope

- 设备列表、设备审批与按设备吊销。
- 自有同步服务器、GitHub Gist、自定义 API 等其他同步位置，以及动态插件加载。
- 字段级或文本级合并，以及冲突副本。
- 增量或差异上传。
- 移动端。
- 对同步位置隐藏同步包的大小与修改时间等元数据。
- 本机数据的定时备份（与合并前快照不同，合并前快照只在同步时产生）。

## Further Notes

- 依据：同类软件调研结论是，KeePassXC / KeeWeb 的「整库加密文件，在客户端按 UUID 与时间合并，删除用墓碑」与我们的方案最接近。主要的事故来源是：最后写入胜出时覆盖了整个文件、把远端清单缺失当成删除、把恢复做成了覆盖。上面的安全阈值、合并前快照和历史同步包就是针对这几类事故设计的。
- 以修改时间裁决依赖设备时钟，时钟严重偏差时结果可能不符合直觉。这一点已接受，不引入逻辑时钟。
- 每轮同步要算两次 scrypt（解密一次、加密一次），每次约 1 秒，同步在后台进行，可以接受。读回检查只比较哈希，不需要再次解密。
- 仓储改为软删除牵涉面广。会话树启动时在内存中组树，加载时必须过滤掉墓碑，否则墓碑节点会出现在树里。
