# 05: Go Sidecar 可诊断性与故障传播

**What to build:** Sidecar 启动、退出或 IPC 异常时，用户看到准确的连接失败/断开，维护者能从应用日志关联进程与错误，而非只有无来源的 EOF。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 接线子进程输出与应用日志，记录启动路径、进程退出码、IPC 生命周期与适当连接关联信息，不记录凭据、私钥或完整敏感负载。
- [x] 区分单连接结束、共享 IPC 结束与进程退出，失败传播到相关连接状态，挂起操作得到明确结束结果。
- [x] 可控地结束测试 daemon/IPC，验证输出捕获、错误传播、资源释放及后续重新拨号；不声称旧远端会话被恢复。
- [x] 用户主动退出与异常断开可区分；日志读取与进程回收不互相阻塞。
- [x] 未复现的既有 EOF 保持根因未知；只有稳定复现和回归测试才能声称根因修复。
- [x] 记录共享 daemon 故障影响，不以单流测试推断全部会话隔离；验证日志无秘密。

## 验收

子进程/IPC 故障、总清理预算与兄弟流、主动关闭和日志哨兵负断言通过；实际 App ILogger 接线已核对，未声称 GUI 文件日志全链路扫描。只输出结构化元数据及白名单原因，不透传原始 stdout/stderr。原始用户 EOF 根因仍未知。证据见 `docs/design/multi-protocol-validation.md`。
