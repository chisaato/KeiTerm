# 多协议终端与通用设备配置

Status: ready-for-human（软件验收完成；工单 04/07/08 剩真实硬件条款，留存工单 09..12 为后续指针）

## Problem Statement

用户希望用同一工作区连接 SSH 主机、Telnet 设备与本地串口，并保留未来 .NET、Go 双引擎选择。目前终端字节流可复用，但连接配置解析、认证、工厂与伴生文件服务仍主要按 SSH 设计。串口路径仅按 OS 保存不足以区分同系统的不同机器；把所有机器覆盖塞入整会话同步对象又存在互相覆盖风险。

## Solution

提供协议感知的会话配置与连接入口，保持终端体验与 SSH 所有权规则。先交付 .NET Telnet、Serial，再补 Go。通过通用、OS 与安装实例三级配置表达跨设备差异，设备配置可同步但独立合并，只由目标安装实例应用。首批三平台设计、Linux 首轮验收，不将未验证平台声称为可用。

## User Stories

1. 作为运维人员，我希望保存 Telnet 会话，以便直接打开设备控制台。
2. 作为运维人员，我希望保存串口会话，以便不必伪造 SSH 主机和端口。
3. 作为用户，我希望配置保留连接类型，以便不会把 Telnet 当作 SSH 拨号。
4. 作为用户，我希望连接类型与实现引擎分开，以便未来可在两种引擎间选择。
5. 作为用户，我希望未支持的引擎明确报错，以便知道实际运行的实现。
6. 作为 Telnet 用户，我希望协商信令不出现在终端画面，以便正常交互。
7. 作为 Telnet 用户，我希望分片、IAC 转义与 NVT 换行正确，以便设备不会收到损坏输入。
8. 作为 Telnet 用户，我希望正确处理 BINARY、ECHO、SGA、TTYPE 与 NAWS，以便与常见设备互操作。
9. 作为 Telnet 用户，我希望对端拒绝可选能力后仍可交互，以便不因缺少 NAWS 而失败。
10. 作为串口用户，我希望设置波特率、数据位、校验位与停止位，以便匹配设备。
11. 作为串口用户，我希望选择无流控、RTS/CTS 或 XON/XOFF，以便使用实际所需的自动流控。
12. 作为串口用户，我希望操作 DTR、RTS 与 Break，以便控制设备；与自动流控冲突时得到明确提示。
13. 作为用户，我希望设备拔出或对端关闭后连接状态准确，以便不面对假连接。
14. 作为用户，我希望主动关闭连接能结束等待，以便不因阻塞读取冻结工作区。
15. 作为用户，我希望无文件系统时隐藏文件入口，以便不触发无效 SFTP/SCP 操作。
16. 作为多设备用户，我希望 OS 默认参数参与同步，以便跨系统复用配置。
17. 作为多设备用户，我希望每台机器有独立设备覆盖，以便同 OS 端口不同也不互相覆盖。
18. 作为多设备用户，我希望离线修改不同设备记录后可合并，以便不丢另一机器的绑定。
19. 作为用户，我希望删除覆盖后回到下层默认值，以便行为可预测且同步不复活旧配置。
20. 作为用户，我希望未启用同步也有设备配置，以便本地连接不依赖云端设置。
21. 作为用户，我希望新机器先确认端口绑定，以便不因同名路径误连。
22. 作为用户，我希望显式把迁移来的目录作为新设备使用，以便保留旧设备的配置归属。
23. 作为 SSH 用户，我希望现有认证、信任、跳板与文件功能保持不变，以便升级不造成回归。
24. 作为 Go 引擎用户，我希望 Sidecar 出错有可追溯日志与失败通知，以便诊断而非猜测 EOF 根因。
25. 作为用户，我希望知道哪些平台和硬件经过验证，以便判断部署风险。

## Implementation Decisions

- 采用已接受的多协议能力与设备配置架构决策；连接拥有视图，重连与断开不泄漏旧世代资源。
- 先进行保持 SSH 行为的协议路由预重构，不在接入前重写整个传输层。终端收发与断开契约复用，可选能力不强制由全部实现提供。
- 解析配置保留连接类型；Telnet 网络默认端口与 SSH 分开，Serial 使用设备端点，不用网络端口承载波特率。导入配置缺失时明确提示，不把 Serial 导入节点当成完整可用配置。
- Telnet 为基础未加密交互连接，明确安全属性；使用流式解析，按方向维护协商状态，正确拒绝未知选项，避免协商循环。Q-Method 可作为实现方法，不是唯一强制算法。
- Serial 参数包含自动流控与手动引脚、Break；手动 RTS 不等于自动 RTS/CTS。模式冲突需明确拒绝或禁用相关操作，不偷偷降级。
- 缺少文件能力时不创建文件服务，隐藏相关入口，文件拖放不得意外发送 SSH 上传命令。非 SSH 流程不弹 SSH 主机密钥或私钥认证。
- 重连遵循连接类型，Serial 不借用 SSH 凭据重试；取消、主动关闭、拔插及资源释放必须有界或明确报告失败。具体策略由行为测试约束。
- 通用设备配置支持对象归属、配置类别、OS 默认与目标安装实例覆盖；只合并显式覆盖字段，删除覆盖恢复下层值，目标设备与修改来源分别表达。
- 设备记录独立同步，具备修改与删除语义；会话删除不遗留可复活的有效绑定。通用存储不接收明文私钥等秘密，仍遵守既有保管库边界。
- 安装实例身份在设备配置使用前创建；同步不替换本机身份，提供显式重建操作且不自动认领旧串口绑定。无需自动硬件指纹检测。
- 仅追加数据库迁移；旧客户端未知字段重写、实体导出和同步删除必须验证。不得声称对任意旧版本天然无损，无法安全往返时必须有可解释的版本门槛或保护策略。
- Go 基础可诊断性可独立推进，协议扩展在对应 .NET 行为契约稳定后接入。进程退出、IPC 失败与单连接失败区分；不承诺 Sidecar 重启能恢复远端连接。
- 实现与测试先 .NET 后 Go，最终补齐对应行为；当前上游缺陷报告与源码机制不构成跨平台稳定性排名。

## Testing Decisions

- 只测试外部行为与持久化结果，不按源码文本、内部调用顺序或 Mock 自我回显验收；沿用既有配置、连接编排、同步、Go 传输及 Avalonia 契约测试的组织方式。
- 优先从配置解析、连接入口、终端收发/断开事件和同步入口验证，避免为每个内部模块新开测试缝。
- Telnet 使用本地真实 TCP 对端：跨块 IAC、转义 255、子协商分片、双向选项状态、未知选项拒绝、NVT、回显、NAWS 接受/拒绝及连接关闭。
- Serial 用虚拟 PTY 验证打开、双向收发、取消、对端关闭和释放；真实设备另验 RTS/CTS、XON/XOFF、引脚、Break 与热拔插。虚拟 PTY 通过不代表真机通过。
- 设备配置验证逐字段优先级、重启恢复、不同安装实例隔离、同设备冲突的确定性裁决、不同设备离线修改不丢失、墓碑、会话删除与重建身份。
- 兼容测试覆盖既有数据库升级、旧配置读写及快照往返；保留 SSH 主机信任、认证、多跳、终端及文件传输回归。
- Go 对应协议复用相同可观测行为契约，并验证 daemon 退出/IPC 中断的状态传播与日志无秘密。共享进程故障影响如实记录，不假定单流隔离已实现。
- Linux 首轮产出自动化及硬件证据。Windows/macOS 区分构建检查、虚拟测试与真实运行；未经运行不得标为已验收。

## Out of Scope

- TLS Telnet、自动登录脚本、Local Shell 与其他新增连接类型。
- Telnet/Serial 带内 ZMODEM/YMODEM 文件传输。
- 移动端 In-Process 集成及移动端 USB 驱动。
- 自动识别数据目录克隆、硬件指纹、设备授权系统。
- 以本次工作替代现有全部设备相关设置，或承诺任意内核故障均可由 Sidecar 隔离。
