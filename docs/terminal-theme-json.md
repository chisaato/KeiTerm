# 通用终端配色 JSON v1

设置 → 终端外观 → 导入外部配色方案 → **导入通用 JSON**，
会打开现有的配色编辑窗口，并自动弹出 JSON 子窗口。
现有配色编辑窗口的 **JSON...** 按钮也可打开同一个子窗口，载入当前名称与配色进行编辑。

在 JSON 子窗口中粘贴或编辑内容，点击“格式化”或“校验”；顶部名称可以覆盖 JSON 中的 `name`。
校验通过后点击“确定”，配色回写到父窗口，可继续通过色块与色值控件调色。
取消 JSON 子窗口不改变父窗口的草稿；取消父窗口则丢弃此次配色编辑。
确认父窗口后才加入设置草稿，点击设置窗口的“应用”或“保存”后持久化。

这是一份独立的终端配色交换格式，不是 KeiTerm 内部配置备份。
它不携带内部 ID、字体、字号、连接信息或 GUI 界面主题。
独立导入会创建新的自定义配色；编辑已有自定义方案会保留其身份与字体设置，编辑内置方案会创建副本。

```json
{
  "schemaVersion": 1,
  "name": "Ocean Night",
  "colors": {
    "background": "#1E1E1E",
    "foreground": "#D4D4D4",
    "cursor": "#D4D4D4",
    "selectionBackground": "#502472C8",
    "ansi": [
      "#000000", "#CD3131", "#0DBC79", "#E5E510",
      "#2472C8", "#BC3FBC", "#11A8CD", "#E5E5E5",
      "#666666", "#F14C4C", "#23D18B", "#F5F543",
      "#3B8EEA", "#D670D6", "#29B8DB", "#FFFFFF"
    ]
  }
}
```

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 必填，整数 `1`。其他版本不会按 v1 猜测解析。 |
| `name` | 名称为 1–120 个字符，不含控制字符。顶部填写名称时可省略 JSON 中的 `name`；有效的 JSON 名称可在顶部改名。 |
| `colors.background`、`colors.foreground` | 必填，`#RRGGBB` 或 `#AARRGGBB`。 |
| `colors.cursor` | 可选，`#RRGGBB` 或 `#AARRGGBB`；省略时使用前景色。 |
| `colors.selectionBackground` | 可选，`#RRGGBB` 或 `#AARRGGBB`；省略时使用 `#50` 加 ANSI 蓝色的 RGB。 |
| `colors.ansi` | 必填，恰好 16 个 `#RRGGBB` 或 `#AARRGGBB` 色值。 |

ANSI 0–7 的顺序为黑、红、绿、黄、蓝、品红、青、白；8–15 为相同顺序的亮色。
八位色值的透明度位于最前面，例如 `#502472C8` 表示透明度 `0x50` 的蓝色。
不支持 CSS 名称、RGB 函数、三位缩写或尾部透明度 `#RRGGBBAA`。
输入的十六进制字母不区分大小写，导入后统一为大写。
从配色编辑器载入 JSON 时，原有 `#RGB` 缩写会展开成六位颜色，八位透明色保持不变。

解析采用严格 JSON：不接受注释、尾随逗号、重复字段或未知字段，字段名区分大小写。
最多接受 256 KiB UTF-8 文本和 16 层 JSON 嵌套。
语法错误会标出行与 UTF-8 字节列，字段错误会标出 JSON 路径，如 `$.colors.ansi[9]`。
格式化保留原始 JSON 中的所有字段与值，格式化成功不代表语义校验通过。

机器可读规范见 [terminal-theme-v1.schema.json](schemas/terminal-theme-v1.schema.json)。

## 使用 LLM 辅助转换

点击弹窗右上角的“复制 LLM 辅助提示词”，将提示词粘贴到使用的 AI 工具中，
再把占位文字替换为已有配色文件内容。提示词包含完整示例、ANSI 槽位顺序、
RGB/iTerm2 数值换算、透明度顺序以及可选色的推导规则。
复制时会将顶部有效名称带入示例；名称留空或无效时使用通用名称。
将 AI 返回的 JSON 粘贴回弹窗进行本地校验。

KeiTerm 只负责复制提示词，不会自动向任何 AI 服务发送配色文件或 JSON。
