## 证据路径与责任

1. 协议路由：配置解析与连接编排入口验证协议保留、默认端口、非 SSH 不收集 SSH 凭据、重连与未知引擎拒绝。路由实施者负责聚焦检查。
2. 设备配置：公开配置服务与同步入口验证逐字段覆盖、重启、独立合并、墓碑、版本拒绝与安装实例身份重建。设备配置实施者负责聚焦检查。
3. Telnet：真实本地 TCP 对端观测终端字节和协议响应，覆盖分片 IAC、NVT、协商、NAWS 与关闭。各引擎实施者负责聚焦检查。
4. Serial：真实虚拟 PTY 对端验证收发和生命周期；自动流控、引脚、Break 与拔插另需物理设备。各引擎实施者负责自动化检查。
5. Sidecar：受控子进程与 IPC 对端验证退出原因、故障传播、等待结束、主动关闭及日志无秘密。诊断实施者负责聚焦检查。
6. 界面：ViewModel 行为与 Avalonia 契约验证协议字段、配置作用域和文件能力入口。界面实施者负责聚焦检查。
7. 最终集成：编排者核对产物与工单，再统一执行构建、完整 .NET 测试、Go 测试与差异检查；后续修改使相关证据失效时重新验证。

## 当前环境限制

- Linux 环境有 `socat`，可运行虚拟串口自动化。
- 尚未提供物理串口设备和接线，不能将 PTY 结果当作 RTS/CTS、XON/XOFF、引脚、Break 或热拔插验收。
- Windows/macOS 未在本机真实运行；交叉编译只能证明相应编译路径，不证明设备行为。
- 原始 SSH IPC EOF 报告的真实根因仍未复现；诊断改进不能被描述为已证明该问题根因。

## 交付结构

- 配置解析保留连接类型，终端通过可选能力声明尺寸与文件支持；SSH 保留既有认证和信任入口，非 SSH 走独立工厂，不创建 SFTP。
- .NET Telnet 使用真实 TCP 与流式 IAC/NVT 协商；.NET Serial 使用 `System.IO.Ports`。两者复用终端收发、断开和重连编排，不将串口波特率塞进网络端口。
- Go 新增独立 `pkg/telnet`、`pkg/serial`，协议 RPC 不借用 SSH 凭据或主机密钥流程。C# 创建会话时不启动 daemon，仅在实际连接时取共享 IPC；取消后的晚到连接响应单独回收。
- 通用串口参数保存于会话配置，OS/安装实例覆盖为独立设备配置实体。编辑仅提交本层显式键，删除某键恢复继承；首次本机端口绑定需明确确认，重建安装身份不认领旧记录。
- 为补齐自动流控，Go 内嵌 `go.bug.st/serial v1.8.0` 的基础通信核心并维护必要差异，来源、固定版本、修改及 BSD-3-Clause 许可见 `engine/internal/serialnative/UPSTREAM.md`。不引入上游 USB 详细枚举组件或 cgo；基础端口名称发现独立实现。许可与来源说明复制到应用输出及发布的 `Licenses/GoSerial/`。
- Sidecar 结构化诊断记录路径、PID、退出码、IPC/流标识和白名单原因，不记录原始 stdout/stderr、认证参数或终端负载。共享 IPC 失效结束关联会话；后续新拨号可以创建新进程，但不会恢复旧 SSH 连接。

## 使用与运行限制

- Telnet 为明文协议，不提供 TLS、自动登录或本地熟模式行编辑。远端未启用 ECHO 时进行本地逐字节回显，远端 `WILL ECHO` 后停止本地回显；密码隐藏依赖远端在密码提示前正确启用该选项。
- RTS/CTS 自动流控与手动 RTS 显式冲突，不会悄悄降级。PTY 对 DTR/RTS 返回“不支持”是合理结果；Break ioctl 被接受不等于已测得电气波形。
- .NET 串口使用有限读写等待并后台释放；Go 串口写入超时只终结对应端口，读取轮询超时不等同空闲断开。本机 PTY 可验证关闭行为，两种实现均不承诺任意故障原生驱动的打开/关闭具有硬实时上界。
- 独立 daemon 的六目标交叉构建不等于 `.NET publish` 跨 RID 封装通过。现有 Sidecar 自动构建按宿主平台编译、命名；跨目标分发仍需核对并提供与目标系统和架构匹配的二进制，不能直接将本机输出视为跨平台发行包。

## 双轴审查

基线 `cea95b3`，审查包含工作区未跟踪的新文件，并非仅比较已提交差异。以下为审查时发现，必修项现已整改：Standards 4 项（含追加的关闭预算），Spec 4 项；跨作用域 RTS 问题在两轴独立重复发现。

### Standards

- 设备作用域保存时，不能因该层 RTS/CTS 生效而清除通用层手动 RTS。
- 设备层字段未显式覆盖时，编辑器必须先继承 OS 值，而不是直接显示通用值。
- 取消测试必须把已取消令牌实际传给生产交互入口，不能只断言空交互实现固定返回值。
- 活着的 IPC 若阻塞帧写入，仅给 RPC 传超时令牌不能保证关闭有界；需覆盖 RPC、Close 帧及 reader 排水的总等待预算，并托管后续清理，不能截断共享帧。

判断性建议：编辑器重复实现覆盖解析容易漂移，优先收敛小型解析逻辑，不借本次审查重写整套界面架构。

### Spec

- 工单 07 要求的基础端口枚举尚需补齐；基础名称发现不等于 USB 元数据能力。
- 编辑已存 Telnet:22 等显式端口时，初始化不能套用用户切换协议时的默认端口推荐。
- 工厂、绑定确认或 Connect 尚在进行时主动断开，必须取消或废弃该次尝试，不能由晚到结果复活标签。
- 跨作用域 RTS 保存不得影响其他设备的通用配置，与 Standards 发现独立重复确认。

上述必修项已由同一独立实现者统一整改，端口发现视觉由界面设计者提供。覆盖字段继承、跨层 RTS 不改写、显式网络端口往返、断开取消在途尝试及基础端口发现均有公开入口回归；共享 IPC 阻塞测试分别阻塞 disconnect/Close 帧，证明关闭在总预算内明确超时而不截断帧，放行后兄弟流仍可收发。原取消测试已改为向真实交互入口传令牌，并用移除生产取消注册的 mutation 验证测试会失败。最终完整测试仍以“最终结果”节为准，不用聚焦结果替代整套验收。

诊断无秘密的直接证据为受控子进程、IPC 与 Go daemon 日志的哨兵负断言；App 的结构化 ILogger 接线已核对，但未声称启动 GUI 后扫描实际日志文件的全链路测试。

## 物理串口验收步骤（尚未执行）

准备支持所需引脚的串口适配器、可控制收发和流控的对端，必要时使用逻辑分析仪。先确认 TTL 电平或 RS-232 电气标准匹配；仅连接隔离测试设备，不在生产设备上尝试控制线或 Break。

同一硬件与参数分别使用 BuiltIn、GoCore 执行，记录操作、结果及失败日志：

1. 发现端口并人工核对实际设备，保存当前安装实例绑定；重开配置和应用后核对端口与有效参数。新安装身份不得自动认领原绑定。
2. 在无流控模式双向发送已知负载，由对端核对字节和顺序；不能仅凭终端“看起来有文字”证明无丢失。
3. RTS/CTS 模式由对端改变 CTS，测量发送确实暂停并在允许后恢复。暂停时长应与配置写超时分别记录：预算内恢复应继续传输，超过预算应明确失败而不是无限等待。
4. XON/XOFF 模式由对端发送 XOFF/XON，验证暂停与恢复；同样记录写超时边界，不把应用层计时暂停冒充驱动自动流控。
5. 在允许手动控制的模式切换 DTR/RTS，用对端或测量仪核对电平变化。RTS/CTS 模式应禁止冲突的手动 RTS；不能以按钮状态代替电气证据。
6. 触发 Break 并核对波形及结束后的正常通信；失败或取消后不能留下持续 Break。
7. 收发期间拔出 USB 设备，核对断开只通知一次、标签不复活、工作区可继续操作；重新插入后核对端口名称，再显式重连，不承诺系统端口名不变。

记录至少包含操作系统/驱动、适配器型号、接线、参数、引擎和观察方式。未取得上述证据前，工单中的物理流控、引脚、Break 与热拔插均保留待验；Windows/macOS 的实际运行还需在相应系统另行执行。
