# 系统原生上下文菜单

「设置 → 常规 → 使用系统原生上下文菜单」写入 `AppSettings.UseNativeContextMenus`，默认关闭。保存或应用后，下次打开菜单立即读取已提交的设置；无需重启。取消未提交的草稿不改变菜单。

## 平台与回退

| 平台 | 实现 |
| --- | --- |
| macOS | AppKit `NSMenu`，使用系统菜单外观和原生菜单跟踪 |
| Windows | Win32 `CreatePopupMenu` / `TrackPopupMenu`，使用系统菜单外观 |
| Linux / 无头平台 | 继续使用 Avalonia 上下文菜单 |

平台句柄不匹配、原生显示失败、菜单包含自定义内容/模板/图标或单选组时，也使用原菜单。`ContextFlyout` 不进行转换。

## 接入与行为

`SystemContextMenuService` 在窗口打开时附加请求路由，在窗口关闭或应用退出时释放监听，覆盖主窗口和弹窗中的标准 `ContextMenu`。

控制器在上下文请求的隧道路由中定位最近的菜单宿主，最后订阅菜单的 `Opening`。原有动态构建和取消逻辑先执行；因此文件管理器的多选同步、动态「打开方式」子菜单及无选中项时取消菜单仍然有效。

原生显示期间将菜单临时挂到宿主的逻辑树，使现有数据上下文和编译绑定（包括 `$parent[Window]`）能够正常求值。`ContextMenuSnapshot` 读取可见项、分隔符、子菜单、禁用和勾选状态。原生跟踪循环退出后，再走原 `MenuItem.Click` 路由执行原命令和参数，并重新检查 `CanExecute`。最后恢复原逻辑父级。取消菜单不执行命令。

macOS 点击回调只记录选中项 ID，不跨 Objective-C 回调边界执行命令；每次显示的菜单和目标对象均在 `finally` 中释放。Windows 在父菜单销毁时递归释放子菜单，创建或挂接失败时释放已创建的资源。

## 验证

- 设置真实控件双向绑定、保存/重新加载和其他偏好保留。
- 真实上下文请求路由、宿主绑定、动态子菜单、勾选和原命令参数。
- 真实 `MainWindow` 会话菜单的编译父级命令绑定与重命名行为。
- 开关变化、关闭/不支持/显示失败的回退、Opening 取消、CanExecute 重新检查和监听释放。
- macOS 独立窗口实测系统菜单、禁用/勾选状态和点击后命令执行；不访问用户数据库或中断已有 SSH 会话。

Windows 的原生显示尚未实机验证。完整测试套件中已有认证测试旧预期、macOS `/run` 路径和终端布局跨线程异常；最后一类可能干扰其他无头测试，专项菜单测试独立运行通过。
