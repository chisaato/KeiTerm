# 代理（防火墙）与会话树选择器设计规格

> 状态：设计规格草案，待审。替代会话编辑器里刚加上的跳板会话名下拉。
> 对标 SecureCRT：全局防火墙列表 + 会话里选「无 / 已有代理 / 选择会话… / 新建…」。

## 1. 目标

手建会话要能走两种出口，而不是在下拉里铺开全部会话名：

1. 全局代理。本轮可建档 SOCKS5、HTTP，以及「援引一条已有会话」。**只有 SOCKS5 和无代理的会话跳板会真正拨号。**
2. 会话上的防火墙字段。下拉只列已保存的代理，另有两项打开对话框：选会话、新建代理。
3. 「选择会话」用目录树，不把树塞进 ComboBox。为此把会话树的展示抽成可复用模块。主窗口的拖放、右键、双击连接不搬进去。

已导入的 ProxyJump（`jump_host_id`）迁进新的会话引用，连接行为不变。

## 2. 不做

- HTTP、SOCKS4 拨号。可以建档，连接时明确失败，设置里标成尚未接入，不假装可用。
- SOCKS5 用户名口令。截图和本机客户端（nekoray / v2ray）都是无认证。`IVaultSecretStore` 只按身份 id 存密钥，本轮不把代理伪装成身份，也不把口令写进 JSON。
- 同一条会话同时挂「SOCKS5」和「跳板会话」。字段只有一个引用。跳板那条会话自己的 SOCKS5 在拨那一跳时生效，这是两条会话各持一个引用，不是一条会话持有两个。
- 端口转发、自动重连、Agent 转发。
- 把 `MainViewModel` 的树命令整段拆成 `SessionTreeViewModel`。那是路线图里的另一项。

## 3. 数据

迁移 **v4**（当前最高 v3）。已发布迁移不改。不删 `jump_host_id` 列。

### 3.1 `proxies`

| 列 | 含义 |
|---|---|
| `id` | TEXT 主键 |
| `name` | 显示名，非空 |
| `sort_order` | 列表顺序 |
| `config_json` | 多态配置 |
| `created_at` / `updated_at` | UTC，走现有 `SqliteValue` |

`config_json` 用 `type` 区分，未知 `type` 加载时跳过该行并记日志，不让整份设置打不开。

```json
{ "type": "socks5", "host": "127.0.0.1", "port": 2080 }
{ "type": "http", "host": "127.0.0.1", "port": 8118 }
{ "type": "session", "sessionId": "…" }
```

SOCKS5 / HTTP 的 `host` 去空白后非空，`port` 为 1–65535。`session` 的 `sessionId` 必须是 GUID。不符合的行视为损坏，与未知 type 同样跳过。

### 3.2 会话引用 `session_details.proxy_json`

不塞进 `options_json`。那一列是可继承的行为覆盖，和出口不是一回事。

```json
{ "kind": "none" }
{ "kind": "proxy", "id": "…" }
{ "kind": "session", "id": "…" }
```

空列等于 `none`。损坏 JSON 按 `none` 处理，并记日志，不阻断加载会话树。

v4 回填：`jump_host_id` 非空的行写成 `{ "kind": "session", "id": "<原值>" }`。此后仓储只读写 `proxy_json`。保存时把 `jump_host_id` 置空，避免旧列和新引用各说各话。连接路径不再读 `jump_host_id`。

`SessionNode.JumpHostSessionId` 保留，仅当 `kind == session` 时由加载逻辑填上，供现有 `JumpChainResolver` 使用。`kind == proxy` 时该字段为 null，代理 id 走单独属性，不把两种 id 塞进同一个字段。

OpenSSH 导入仍产生会话跳板，写入 `kind: session`，不写 `jump_host_id`。

## 4. 连接

`SshConnectOptions` 增加可选的无认证 SOCKS5：`host` + `port`。空则直连。

拨号只走现有 SSH.NET 路径。`SshJumpChain.BuildConnectionInfo` 在**最外层直连**时使用 SSH.NET 的 `ConnectionInfo(..., ProxyTypes.Socks5, host, port, "", "", methods)`。跳板链内部的 `127.0.0.1` 转发端口不套代理。

一条会话的出口：

| `proxy_json` | 行为 |
|---|---|
| `none` / 空 | 直连。与现在相同 |
| `session` | 现有跳板链。对方自己的 `proxy_json` 在拨那一跳的最外层 TCP 时生效。所以「目标经跳板，跳板经本机 SOCKS5」是通的 |
| `proxy` 且 type 为 `socks5` | 本会话最外层 TCP 走该 SOCKS5，不再另挂跳板 |
| `proxy` 且 type 为 `http` 或其他 | 不连接。错误写明「此代理类型尚未接入拨号」 |
| `proxy` 或 `session` 的 id 已删除 | 不连接。错误写明目标已删除。编辑器里打开时保留原 id，显示「已删除」，不因打开就清空 |

终端、SFTP、SCP 都经 `SshDialer`，因此共用同一条 SOCKS5 规则。日志可以记代理 host:port，禁止出现口令字段。本轮没有口令可记，也不要为「以后也许有」把密码参数写进日志模板。

不改 Tmds.Ssh。当前默认引擎就是 SSH.NET。

## 5. 界面

### 5.1 设置 › 代理

表格列：名称、类型、主机、端口。`session` 类型的主机列显示被援引会话的 `名称 (user@host:port)`，端口留空；会话已删除则主机列显示「已删除」。

底部：添加、编辑、删除。编辑是对话框，不是表格内联。

类型：

- SOCKS5：主机、端口。无用户名口令字段。
- HTTP：同样的主机、端口。保存时不拒绝，说明文字写「尚未接入拨号」。
- 已有会话：按钮打开 §5.3 的树，结果写入 `sessionId`。

删除被会话引用的代理：允许删。引用方按 §4 在连接时失败，编辑时显示「已删除」。

### 5.2 会话编辑器

连接页、身份下面。撤掉现在的跳板会话名 ComboBox（`JumpHosts` 铺开会话列表的那一版）。

下拉项，按此顺序：

1. 无
2. 已保存代理的名称，按 `sort_order`
3. 选择会话…
4. 新建…

「选择会话…」和「新建…」不是持久化的值。点下去打开对话框；取消则下拉回到打开前的选择。确定之后，下拉显示所选会话名或新建代理的名称，保存进 `proxy_json`。

已保存的引用若指向已删除的代理或会话，下拉保留该项，文案「已删除」，不改选择就原样写回。

### 5.3 选择会话对话框

标题「选择会话」。上面是筛选框，中间是目录树，下面确定 / 取消。

- 文件夹只能展开，不能作为结果。确定按钮在选中文件夹或未选中时不可用。
- 双击会话等于确定。双击文件夹等于展开或收起。
- 筛选匹配名称，文件夹若有命中的子孙则保持可见并展开。
- 不能选自己。不能选 `JumpHostPicker` 会排除的成环或超层会话。这些节点仍在树上，显示为不可选，避免树被挖空后看不出结构。
- 数据用打开对话框时的会话树快照，对话框期间不重新加载。

### 5.4 树模块

抽的是展示，不是主窗口的命令。

模块对外只需要：节点列表、筛选文本、当前选中、选中变更、以及「这项能不能选」。条目模板、缩进、展开线和现有 `KeiTreeViewItem` 主题留在这一处，主窗口和对话框都用它。

不进入该模块的：拖放、右键菜单、双击连接、新建、删除。这些仍在 `MainWindow`。若抽取会碰坏拖放，停在共享条目模板，不要把拖放逻辑搬进控件。

## 6. 测试

行为测试，不测调用顺序，不按源码文本断言。

- `proxy_json` / `config_json` 往返：三种 kind、三种 type；损坏 JSON 不抛到树加载。
- v4：有 `jump_host_id` 的旧库迁成 `kind: session`；迁移后再保存，`jump_host_id` 为空且 `proxy_json` 仍在。
- 会话编辑器：下拉不含会话名列表；选代理写出 `kind: proxy`；选会话写出 `kind: session`；选「无」清空；已删除 id 打开后不丢。
- `JumpHostPicker` 的排除规则继续有效，对话框的不可选集合用它，不另写一套循环判断。
- `BuildConnectionInfo`：有 SOCKS5 时最外层 `ConnectionInfo` 的代理类型是 Socks5，host/port 正确；拨到 `127.0.0.1` 转发端口时不带代理。
- 编排：目标的出口是会话时，跳板链与现在一致；该跳板自己的 SOCKS5 出现在那一跳的直连选项上，不出现在后续转发端口上。HTTP 代理使连接在拨号前失败，且错误文本能区分「尚未接入」和「已删除」。

不要求本轮起一个真实 SOCKS5 服务器。代理类型和端点能在 `ConnectionInfo` 上断言即可。真链路留到已有 sshd 集成测试能挂上本地 SOCKS5 时再加，不阻塞这一轮。

## 7. 风险

| 风险 | 处理 |
|---|---|
| 树抽取带崩主窗口拖放 | §5.4：拖放留在主窗口；抽不动就只共享模板 |
| `jump_host_id` 与 `proxy_json` 双写漂移 | 迁移后只写 `proxy_json`，保存时清空旧列 |
| 用户配了 HTTP 却以为能连 | 建档说明 + 连接错误都写「尚未接入拨号」 |
| 本地 SOCKS5 没开 | 作为普通连接失败呈现，不单独做健康检查 |
