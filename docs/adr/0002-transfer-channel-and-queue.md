# 传输走每连接一条专用传输端点；传输队列不持久化

SFTP：每个连接额外建立一条专用传输连接（首次 Acquire 才建立，无未归还租约且空闲 60 秒后关闭，随所属连接关闭）。并发任务在这条连接上各开独立文件流；单个流不跨任务共用。浏览用的文件通道不承担传输。

SCP：另建一个 `ScpRemoteFileSystem`，与浏览实例隔离。Acquire 时才连接，连接与关闭串行。该实例不能并发，队列把 SCP 并发数固定为 1。生产端点创建失败时传输不可用，不回退浏览通道；浏览仍可用。

传输队列只在内存中，退出应用即清空，不新增续传元数据。同一次运行里，只有写流成功打开后记下的源事实、路径所有者世代仍有效、且源大小和修改时间仍一致时才能续传。上一轮运行留下的部分文件没有可信来源，必须重传。大小相同不是校验和。

## Considered Options

- **每个并发占一条 SSH 连接**：暂不采用。SSH.NET 无法在已有连接上再开 SFTP 子系统，每条连接都要重新登录，需要人工输入口令的主机会反复弹框。高延迟大带宽链路跑不满时再作为可选项加入。
- **复用浏览用的文件通道**：放弃。传输会挤占列目录；SCP 的单客户端也不能和浏览并发。
- **持久化传输队列，或靠磁盘上的部分文件跨次运行续传**：放弃。恢复要重新取得凭据并重建连接；没有可信源历史时，续传可能把旧前缀接到已变化的源上。不为此新增元数据。
