# 连接类型与实现引擎分开，按实际能力提供伴生功能

Status: accepted（2026-11-09，待实现）

SSH、Telnet 与 Serial 共用终端交互和生命周期，但不能共用强制 SSH 认证、主机密钥与文件系统的连接流程。连接类型决定通信语义，实现引擎决定由 .NET 或 Go 执行；承载通道是独立的分析维度，不强制形成固定三层框架。Serial 是设备连接类型，不伪装成网络应用协议。

通用连接入口按类型分派，SSH 专有编排保留在 SSH 适配边界内。文件系统、动态尺寸与带内传输按实际能力提供；Telnet NAWS 等能力还取决于运行时协商。没有文件系统时不初始化文件服务并隐藏相关入口，不返回假文件系统。具体能力接口形状留给实现，不预先规定每协议复制一套复合工厂。

先实现 .NET Telnet 与 Serial，再补齐 Go；这基于调试路径和当前串口流控要求，而非未经测量的性能或可靠性排名。显式选择的引擎缺少能力时清晰报错，不静默回退。既有 SSH 连接所有权与安全约束不变。
