# 同步采用单个 age 加密的整库快照，在客户端按实体合并，不做设备管理

KeiTerm 没有自己的服务器，同步位置只是用户自选的本地目录、WebDAV 或 S3 兼容存储。因此同步包是**一个**用 age 口令模式（scrypt）加密的整库快照；每台设备都执行「下载 → 解密 → 按同步实体合并 → 加密 → 上传」。全部应用数据都参与同步，包括秘密与设置，只排除本机专属项。加入同步只需要知道同步口令。不做设备列表、审批或吊销，更换同步口令即重新加密整个同步包，起到踢出旧设备的作用。

合并规则沿用 KeePass 系的做法：每个同步实体以最后写入为准（比较修改时间，平局比较设备标识）；删除以墓碑传播；实体在被删除之后又被修改，则保留该实体。同步位置支持 ETag 条件写时使用条件写；不支持时直接上传，再读回检查写入方，必要时重新合并。

## Considered Options

- **每个实体一个远端文件 / 只追加的操作日志**：放弃。数据量只有 KB 到 MB 级，全量传输的成本可以忽略；逐对象同步要处理部分上传、清单不完整被误当作删除等问题（Joplin 在 S3/R2 上出过事故），复杂度远超收益。
- **Git 式完整版本管理**：放弃。实现成本高；同步位置保留最近若干个历史同步包、本机保留合并前快照，已足以从误合并中恢复。
- **随机主密钥由口令包装，或 age X25519 身份由口令包装**：放弃。这类方案的好处是改口令不必重加密数据，但我们本来就要把「改口令 = 重加密」当作吊销手段；单文件的口令模式保证 `age -d` 能直接解开，同步位置上也只有一个对象，不存在多个文件之间的一致性问题。
- **只同步元数据、秘密留在本机（原设计 05 的模式 A）**：放弃。同步秘密正是做端到端加密的目的。
- **设备列表与按设备吊销**：放弃。没有服务器来执行吊销；对于共享同步口令的设计，吊销只能靠更换口令。

## Consequences

- 每次同步都要计算一次 scrypt（约 1 秒），这个代价可以接受。
- 没有条件写的同步位置，在几乎同时同步的极短窗口内仍可能被另一台设备覆盖；被覆盖一方的修改仍在其本机，下次同步时会重新合并进来。
- 墓碑保留 180 天。离线超过这个时长的设备，可能把已删除的实体带回来。
- 取代 ADR-0003 中「连接元数据不参与同步」一句：连接元数据描述服务器，随会话同步，按键合并。
